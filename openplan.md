# Make the JIT compile the slow functions of dreams

Goal. Take the tier from "the strict numeric spine" to "any function whose shape is compileable, crossing into the interpreter wherever a callee is not" — so that the 17 hottest self-compile functions (lower_expr, check_expr, skip_trivia, map, stream, fold, parse_*, token_at, …; together well over half the profile) stop being refused. Exit criterion: "functions compiled" (--stats) climbs well past 19, and a self-compile wall-clock and --profile share move with it, with the seven benchmarks within the placement-noise floor.
Why this is safe to do at all: allocation never collects (a collection runs only at a safepoint; dream_rt_float already allocates from compiled code). So the tier can build lists/arrays/maps/strings/atoms/closure values with no spill machinery — the "de-pin the collectors first" stage from the old plan is not a prerequisite. The real blocker is that compiled code has no way to express "a value not yet evaluated", so it snips laziness and correctly refuses wherever that would move an error. The plan's core is suspension: compiled code learns to build real thunks against a snapshot of its own slots, which is exactly what the interpreter does (thunk_for + make_frame, interp.cpp:2178, heap.hpp:113).

# Stage A+B — data structures, the honest way (one milestone)
Lands the two halves together because elements become suspended, not evaluated: without B, A is only the hand-shaped subset.
A. New opcodes, emitted. Add to op_is_supported (jit.cpp:399) and the emitter's node():
- ConstAtom — an immediate; a load through rt_'s remapped atom table (atoms are remapped once at load, runtime.hpp:163, so this is a constant load of a stable Value, no helper, no GC concern).
- ConstStr — a load from proc->string_cache[idx] at point of use. The cache is a process root; the string pointer inside it may move, but every boundary between this load and the use is pinned (force/native/apply all pin), and each OSR resume re-enters the body from the top so the entry re-fetches. No tenuring needed.
- MakeList/MakeArray/MakeMap — heap make_cons/make_array/make_map (heap.hpp:100-106) behind small dream_rt_* helpers taking the element values in registers.
- Get, Set — call the interpreter's container_get/container_set (interp.cpp:1289/1336). Get's container and key are evaluated eagerly (the interpreter does too). Get else d and Set's value are suspended → they need B (see below); a plain Get with no else needs no frame at all.
B. Suspensions from compiled code — the mechanism. dream_rt_suspend(proc, node_idx, snapshot) where the snapshot is a fresh FrameObj copy of exactly the slots the subexpression can read (make_frame, then fill; young object, collector-safe, no barrier). This is thunk_for at one small allocation per suspension, and it is the cost of registers. With it:
- MakeList/MakeMap/Set/Get-else elements are thunked against the snapshot — laziness preserved, nothing that raises moves. The old eagerly_safe gate (jit.cpp:686, the "list element may be computed" trick) is subsumed: it was an optimization, and staying eager where it was sound stays possible, but the gate that refused everything else dissolves.
- Native unclaimed args are suspended, not gated. check_apply's !strict && !eagerly_safe → refuse (jit.cpp:630) becomes "anything in an unclaimed position is suspended" — identical to the interpreter, which is the whole of range, replicate, from, repeat, zip, stream, map, fold being refused today via core.cons's mask 0 tail.
- The strictness admission relaxes from a soundness rule to a speed knob. For a self call, an argument landing in a param that is neither forced-anywhere (strict_of) nor carried may be suspended instead of evaluated — and suspending is always possible. So a root no longer has to force every parameter on every path; eager evaluation survives exactly where the numeric loops want it (strict params get computed args — sum's fused loop is untouched), and laziness elsewhere becomes exactly the interpreter's. strict ∪ carried stays the machine-eager set; the rest goes through B. Peers are unchanged — machine-called with eager args, they stay all-strict. Float slots: non-strict+float params are boxed by the existing boundary code; refuse only that corner.
- MakeClosure/Capture — build_closure (interp.cpp:1692) with captures read raw for Local captures and snapshot-suspended for computed ones. Cheap, and the front half of Stage C.
Checkpoint A+B. Lexer/parser cluster + list constructors admit: skip_trivia, stream, token_at, peek_kind, char_len, parse_apply, gather_args, range, zip, take, drop, index_of_from, in_scopes-loops … Re-profile: compiled-count up, self-compile wall down, benchmarks unchanged, just test-all green (new dream/tests/programs/*.dr lines hold the honest-laziness lines: an element that divides by zero raises only when demanded; from 0 stays infinite under the JIT; a suspended arg nobody looks at doesn't raise).
# Stage C — closure values + interpreted calls (the big unlock)
Two pieces:
1. Interpreted-apply fallback. dream_rt_apply(proc, callee_value, arg_count, …): push snapshot-thunked (or in-hand) args and enter the machine the slow way, pinned, via do_apply/enter_function re-exposed beside force_whnf (interp.cpp:1663, apply at 1609). A saturated-call site evaluates through peer_admits first (machine call today); on refusal it falls back to dream_rt_apply on the global's closure value instead of refusing the whole function. kMaxPeers and PeerSet::sound stop being refusal reasons — they bound machine peers only.
2. Closure values as callees. A call of Op::Local/Field (the f in map f xs) compiles to dream_rt_apply. Combined with 1, the all-or-nothing closure rule (check_apply's last branch, jit.cpp:638) becomes a prefer-compile, fall-back-interpret rule. Every map/fold/filter/any/all/keep and every helper lower_expr/check_expr call compiles, with unadmittable leaves interpreted per call.
A compiled→interpreted call is a machine call that returns via the existing status path, so depth stays bounded by the stack-budget/deopt machinery (JIT_DEEP), and a tail-position interpreted call is a call-then-return (its recursion is heap). Profile stays honest: the interpreted callee has its own frame, so its reductions charge to it.
Checkpoint C. map/fold/filter/in_scopes/lower_expr/check_expr admit (Step 0's reasons will say which surface next). Self-compile wall again; benchmarks again; --stats --profile 1 totals agree; fuzzer + heap-verified + no-JIT runs green.
# Stage D — measure, choose, stop
Re-run the full refusal dump. Remaining picky work only if a specific function justifies it: raise kMaxPeers, or a body-size/LLVM-cost cap for huge bodies (mapfilter shows ~10 ms/function compile; lower_expr's body may cost more than it pays, and the right answer may be "tier declines very large bodies" — measured, not guessed). Remove whatever of eagerly_safe is now dead.
Guardrails held across every commit
- Benchmarks before/after each stage; nothing numeric may move past the placement-noise floor (fib alone can't resolve 3%; diff instruction streams / use the A/B discipline in CLAUDE).
- Tier agreement is the suite: every test and new program under both tiers; just test-all (fuzzer, heap-verified, no-JIT); new laziness programs under dream/tests/programs/.
- VM-only → no compiler change, no bootstrap move, byte-identical images (bootstrap-check must pass).
- Timeout on every VM run.
